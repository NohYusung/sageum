# Study Note Writer

이 skill은 `~/sageum-agent/data` 아래에 개념을 조사하고 자세한 노트를 작성하는 요청에 사용한다.

## 필수 규칙

1. `~/sageum-agent/data/<topic>/` 형태의 주제 폴더를 새로 만들거나 기존 폴더를 사용한다.
2. `webhook.md`, `oauth.md`, `ietf.md`처럼 주제명이 드러나는 Markdown 파일에 작성한다. 이런 study note에는 `README.md`를 사용하지 않는다.
3. Mermaid 다이어그램은 문서 상단에 한 번만 넣는 것이 아니라, 문서 전체에 걸쳐 포함한다.
4. 각 주요 섹션에는 그 섹션의 구조, 흐름, 비교, 의사결정 로직을 한눈에 이해할 수 있는 Mermaid 다이어그램을 최소 1개 포함한다.
5. 어떤 섹션이 별도 다이어그램을 둘 만큼 크지 않다면, 다이어그램 없는 섹션으로 두지 말고 인접 섹션과 병합한다.
6. 실제로 사용한 출처를 Markdown 링크로 정리한 `참고 링크` 섹션을 포함한다.

## 출처 규칙

- 1차 자료나 공식 자료를 우선 사용한다.
- 주제가 시의성이 있으면 작성 전에 먼저 웹 검색을 한다.
- 여러 자료를 사용했다면 자료별 요약을 나열하지 말고, 하나의 흐름으로 재구성해 종합한다.

## 기본 노트 구조

사용자가 다른 구조를 요청하지 않았다면 아래 구조를 기본으로 사용한다.

1. 한 줄 요약
2. 왜 중요한가
3. 핵심 개념
4. 아키텍처 또는 흐름
5. 중요한 세부사항, edge case, tradeoff
6. 실전 예시
7. 용어집 또는 빠른 복습
8. `참고 링크`

이 기본 구조를 사용할 때는 1번부터 7번까지의 주요 섹션마다 최소 1개의 Mermaid 다이어그램을 포함한다. 마지막 `참고 링크` 섹션만 다이어그램이 없어도 된다.

## 작성 규칙

- 사용자가 다른 언어를 요청하지 않는 한 한국어로 작성한다.
- 깊이 있게 설명하되, 훑어보기 쉽도록 구조화한다.
- 첫 번째 Mermaid 다이어그램은 문서 앞부분에 배치한다.
- 단일 overview 다이어그램 하나로 끝내지 않는다. 각 주요 섹션마다 Mermaid 다이어그램을 추가한다.
- 같은 전체 구조 다이어그램을 반복하기보다, 섹션별 내용을 설명하는 다이어그램을 선호한다.
- 섹션이 너무 작아 의미 있는 다이어그램을 만들기 어렵다면, 섹션을 더 적고 큰 단위로 재구성해 "주요 섹션마다 다이어그램 1개" 규칙을 만족시킨다.
- 섹션 제목은 내용을 잘 드러내도록 작성한다.
- 파일명은 주제가 드러나도록 정확하게 짓는다.

## 이름 짓기 가이드

- 폴더명: 짧은 kebab-case를 사용하거나, 사용자가 이미 특정 주제 문자열을 준 경우 그 문자열을 사용한다.
- 파일명: 주제가 드러나게 짓고, 가능하면 단수형을 사용한다.

예시:

- `~/sageum_agent/skills/study-note-writer/references/cross-origin-policy.md`
- `~/sageum_agent/skills/study-note-writer/references/dependency-injection.md`
- `~/sageum_agent/skills/study-note-writer/references/electron.md`
